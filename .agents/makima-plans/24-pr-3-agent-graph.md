### Goal

Implement issue #24 PR 3, **Agent manager and graph**, on top of the landed PR 1 lifecycle contract and PR 2 shared actor. Add one `maki-agent` manager per outer TUI session that is the sole production factory for that session’s root and descendant actors, tracks nested parent-child topology by `AgentId`, centrally enforces graph/concurrency limits, and provides race-safe node/subtree cancellation while preserving current TUI, `maki.agent.session`, and task compatibility behavior.

### Implementation Summary

Add a dependency-neutral manager layer under `maki-agent/src/manager/` above the existing `AgentActorHandle`. The actor remains the only FIFO/history/outcome/lifecycle scheduler for one agent; the manager owns the outer-session graph, actor registry, runtime tasks, topology, spawn authority, global active-turn permits, and graph-wide cancellation/shutdown. No second per-agent scheduler or history store is introduced.

One `SessionRuntime` in `maki-ui/src/event_loop.rs` owns one manager. `AgentHandles` becomes the root-node compatibility adapter rather than directly constructing an actor. `maki-lua/src/api/agent.rs::session` creates a child through an internal, turn-scoped manager capability carried by `ToolContext`, so the same path naturally creates grandchildren when a managed child invokes `maki.agent.session`. The manager-generated `AgentId` is runtime identity; `tool_use_id`, `SubagentInfo.parent_tool_use_id`, task IDs, TUI `run_id`, and provider history tool-use IDs remain compatibility/presentation/protocol correlation only.

Use the operator-selected default limits, configurable in `[agent]`:

- `max_concurrent_agent_turns = 8` per outer session;
- `max_agent_depth = 4` edges below a root at depth 0;
- `max_children_per_agent = 16` live direct children;
- `max_live_agents = 64`, including the root.

Closed/removed nodes remain inspectable for the manager lifetime but do not consume live-node or fan-out capacity. Completed, failed, and turn-cancelled agents remain live and reusable. Nested spawning is manager-allowed by default; PR 4 will intersect it with immutable per-agent policy and spawn ceilings.

Primary touch points:

- New `maki-agent/src/manager/{mod.rs,types.rs,manager_error.rs,tests.rs}` (split further only where SRP warrants it), exported from `maki-agent/src/lib.rs`.
- `maki-agent/src/actor/{mod.rs,types.rs,runner.rs,queue.rs}` for narrow manager integration hooks, runner-level admission, and the atomic reusable cancellation cut.
- `maki-agent/src/tools/mod.rs`, `maki-agent/src/agent/run.rs`, and `maki-agent/src/types.rs` for opaque current-agent/turn manager context propagated into tool dispatch and non-serialized `SubagentInfo.agent_id` runtime metadata.
- `maki-config/src/lib.rs` plus generated configuration docs for validated graph-limit fields.
- `maki-storage/src/session_lock.rs` for identity-safe owned lock leases and backward-compatible ephemeral records.
- `maki-ui/src/event_loop.rs`, `maki-ui/src/app/session.rs`, `maki-ui/src/agent/mod.rs`, `agent_loop.rs`, and `command_router.rs` for inert runtime preparation, one manager per `SessionRuntime`, root creation, compatibility routing, and graph shutdown.
- `maki-lua/src/api/agent.rs`, `maki-lua/src/api/util/ctx.rs`, and `maki-lua/src/runtime.rs` for manager-created child actors, exact invocation scope, nested propagation, compatibility IDs, and blocking child-wait permit yielding.
- `plugins/task/init.lua` to remove the blocking composite's separate outer semaphore acquisition, retain/deprecate the process-wide semaphore as the unmanaged frontend fallback until PR 9, and pass that fallback to `maki.agent.session` without double-enforcing managed turns; keep task API names/result shapes/polling behavior unchanged.

Scope boundaries:

- Do not move model/provider, prompt, tools, permissions, mode, request options, or immutable queued policy ownership into nodes; PR 4 owns that.
- Do not add public Lua `Agent`/`AgentRef`, spawn/send/wait APIs, structured completion subscriptions, or migrate task polling; PR 5 owns that.
- Do not change persisted session/history format, persist topology, migrate stored subagent transcripts, or define restart recovery; PR 6 owns that. The ephemeral cross-process `.lock` record may gain a backward-compatible owner token solely to make lease heartbeat/release identity-safe.
- Do not add guest presets/modes, graph UI/tree navigation, arbitrary-agent focus, or migrate ACP/headless/SDK/print; PR 7/8/9 own those.
- Preserve direct unmanaged headless/ACP/SDK paths for now. “Sole factory” is enforced for the TUI outer sessions migrated in this PR and for all descendants spawned inside them; remaining direct frontend construction is an explicit PR 9 compatibility exception. Direct `AgentActorHandle::spawn` remains available only to the manager, actor tests/test support, and the documented deferred unmanaged frontends.

### Implementation Plan

#### Phase 1: Define the manager, graph, and nominal handles in `maki-agent`

1. Add `AgentManager`/`AgentManagerHandle` with one `Arc<ManagerInner>` containing a short-held mutex over graph state, the selected `AgentLimits`, a manager generation/identity, and one shared active-turn limiter. Never hold the manager lock across an await, backend call, actor call that can re-enter tool dispatch, or task join.
2. Model graph nodes by stable `AgentId`. A private live node record owns:
   - optional `parent_id` and immutable root id/depth;
   - an ordered or deterministically sortable child-id set;
   - the `AgentActorHandle` and its runner task/join ownership;
   - live/closing/closed/removed graph lifecycle;
   - optional compatibility metadata such as label and `spawned_by_tool_use_id`, explicitly non-authoritative.
   Expose immutable `AgentRef`/`AgentNodeSnapshot` projections with identity, parent, root, depth, children, actor status/lifecycle, and graph lifecycle. Visibility is descriptive only and cannot be upgraded into control by supplying an id.
3. Make manager creation and actor creation two-phase and rollback-safe:
   - `create_root` is host-only, succeeds exactly once, reserves the root node under the graph lock, constructs the adapter-supplied backend/actor without the lock, then commits the live node or rolls back the reservation on failure;
   - `spawn_child` validates a manager-issued authority, parent liveness, graph generation, limits, and optional compatibility metadata atomically; reserves the child edge/id; builds the backend/actor outside the lock; then commits or rolls back;
   - no public API accepts a caller-chosen parent as sufficient authority, and guessed `AgentId`s never grant control;
   - all production TUI root/descendant construction routes through these methods.
4. Introduce a small opaque internal capability contract, not the complete PR 4 security/policy system:
   - a host capability can create/control the root and graph;
   - a turn-scoped descendant-spawn capability contains manager generation, current `AgentId`, current `TurnId`, and an unforgeable manager-issued nonce; every spawn/yield validates it against a manager-side active-turn entry before any graph lookup;
   - one non-cloneable RAII `ManagedTurnGuard` uniquely activates the nonce after managed execution admission and revokes it on every drop path, including setup failure, permit-acquisition cancellation, ordinary completion, cancellation, backend future drop, and unwind; cloned `ToolContext`s carry only a cloneable restricted token, never the guard;
   - cloning the token may preserve or narrow scope but cannot change the parent/current node, and a retained clone in a detached future becomes unusable as soon as the guard revokes the active entry;
   - node ids, topology, tool-use ids, and UI focus are never bearer authority.
   Keep representation and nonce validation private behind methods so PR 4 can add policy-derived ceilings without changing call sites. Test replay from a cloned detached context after completion/cancellation/setup failure, wrong-manager tokens, and a reused `TurnId` with the wrong nonce.
5. Define `AgentLimits` and typed `ManagerError` cases for missing/duplicate root, unknown or non-live parent/node, stale/wrong-manager capability, inactive turn, spawn denied, depth exceeded, direct-child limit, live-node limit, concurrent execution closure, graph shutdown, and factory failure. Errors must include actionable bounded context but no capability secret.
6. Add `[agent]` config fields in `maki-config/src/lib.rs` for the four selected limits, with constants at the top of the file, generated metadata/descriptions, `min = 1` validation, and cross-field validation where required (at least `max_live_agents >= 1`; depth is measured with root = 0). Convert safely to `usize` at the manager boundary.
7. Add structured tracing for manager generation/id, agent/root/parent ids, depth, graph revision, live count, active-turn count, limit rejection, spawn commit/rollback, cancellation cut, and shutdown. Do not add a dependency unless existing `Mutex`, `async_lock`, `event_listener`, and `smol` primitives cannot implement the contract.

#### Phase 2: Centralize active-turn admission without recursive deadlock

1. Put managed admission in the actor runner before backend construction, then gate the admitted future on every poll:
   - add an optional manager-owned `ManagedTurnAdmission` hook to manager-created actors; after the actor installs `ActiveCancel` but before it calls `ActorBackend::run_turn`, race asynchronous physical-permit acquisition against that turn's cancel/reason token;
   - cancellation/close/shutdown before acquisition makes the existing actor runner synthesize the same not-entered result already used by its pre-backend cancellation path: an admitted non-root ticket receives exactly one `TurnOutcome::Cancelled`, while a root that never entered has no retained/delivered outcome. The backend method is never invoked, so its borrowed future is neither constructed nor polled;
   - after acquisition, create the unique `ManagedTurnGuard` and shared `TurnPermitLease`, invoke `ActorBackend::run_turn`, and wrap only the returned borrowed future in `ManagedExecutionFuture`; do not attempt to store a self-referential backend/history future;
   - on every poll, the lease gate runs first: if suspension count is zero but no physical permit is held, asynchronously reacquire and return `Pending`; never poll an already-started opaque backend without a permit, including after cancellation, because provider/Lua cleanup can execute arbitrary code.
   Controls and standalone compaction bypass managed admission unless they enter a model turn. Count active work, not live actors or queued turns.
2. Preserve per-agent FIFO: actors may queue independently, but no more than `max_concurrent_agent_turns` managed turns execute across the graph. Permit acquisition races actor close/shutdown/cancellation, so a queued actor waiting for capacity terminalizes correctly rather than hanging.
3. Propagate through `TurnContext` -> adapter backend -> `AgentParams`/`ToolContext` the restricted active-turn token and `TurnPermitLease` tied to current manager, `AgentId`, `TurnId`, and nonce. `Agent::tool_context()` copies these to concurrent model/Lua tool invocations. Nested `AgentContext::from` and `to_tool_context` retain them while still clearing `tool_use_id` and `live_sink` as today. Do not make a retained `LuaSession` the owner/source of the parent turn lease; it stores only its own child `AgentId`/manager relation.
4. Define the concrete blocking-descendant suspension protocol used by compatibility `LuaSession::prompt` without polling an unowned opaque parent future:
   - only a manager-validated wait by the active parent turn on its own descendant may register a blocking wait; unrelated turns, background `send`, UI input, detached callbacks, and unmanaged sessions cannot yield the lease;
   - registration creates shared `ManagedPromptWait` completion/cancel state plus an independently driven watcher task. A manager/reaper-level `WatcherRegistry`, not the lease, owns watcher `smol::Task` handles. The lease stores only watcher ids, cancellation triggers, and completion-state handles; each watcher captures the lease state and owns one non-cloneable `PermitSuspensionGuard`, so no strong lease -> task -> lease cycle exists. The first guard atomically releases the physical permit and later guards increment the count without releasing twice;
   - the watcher races the exact child `TurnTicket` against prompt-drop cancellation and the optional prompt timeout. Exactly one branch stores a completed outcome/error when applicable, retires the guard once, atomically removes the watcher id from the lease's active-registration set, and marks the registry record reapable. It never removes or drops its own task handle: only an external registry/reaper drain joins the terminal task and then removes that retained handle. Lease retirement, registry completion marking, and post-join removal are independently idempotent. Prompt drop signals only its watcher and lets the child keep running, preserving asynchronous-session behavior; timeout permanently closes the child as today, stores the timeout error, and retires once. Watchers run no Lua/model/provider continuation; the manager/reaper registry retains their handles until joined, while watcher-held shared state keeps the lease alive only until guard retirement;
   - `LuaSession::prompt` awaits the watcher state, then awaits the lease's shared owned-generation barrier before reading presentation/cumulative usage, building a result, returning to Lua, or executing any post-wait continuation. Child completion can therefore decrement suspension counts while the opaque parent backend remains completely unpolled. An early completion remains parked while sibling guards exist;
   - `PermitSuspensionGuard::drop` is synchronous and idempotent: it decrements exactly once, marks `reacquire_required` and advances/wakes the shared resume generation when the last suspension disappears, and wakes the outer `ManagedExecutionFuture`; it never blocks or acquires a semaphore. Watcher setup failure rolls back registration synchronously before returning an error;
   - the outer poll gate is the only authority allowed to restore physical ownership. After asynchronous reacquisition it marks the shared generation owned and wakes completed prompt waiters; until then neither the outer future nor any prompt continuation may poll parent Lua/model/tool code;
   - parent cancellation revokes turn/spawn authority, snapshots/signals all watcher ids registered to the lease, and wakes the gate but does not bypass limiting. Once suspensions reach zero, the execution future reacquires a physical permit before polling the backend to observe cancellation, run cooperative cleanup, emit/retain its terminal outcome, and release;
   - `ManagedExecutionFuture::drop` is the total abnormal-teardown boundary: synchronously mark the lease closing, reject new wait registrations, signal every registered watcher, release any held physical permit, and only then revoke/drop `ManagedTurnGuard`. This terminal path never reacquires because no parent continuation remains. Watcher cancellation/drop still retires each guard exactly once; `WatcherRegistry` retains and joins those tasks/state after outer drop, and outer-drop races with child completion, timeout, prompt drop, cancellation, or unwind use one atomic winner per watcher;
   - manager shutdown first closes new graph/turn admission, marks each lease closing and signals its wait watchers, then lets already-started managed turns reacquire in bounded sequence, observe shutdown cancellation, terminalize, and release. Compute one absolute deadline at shutdown entry using the existing three-second TUI `AGENT_SHUTDOWN_TIMEOUT` policy, relocated/shared with the manager rather than deriving it from provider request timeouts. Return `ShutdownReport { joined, timed_out }`; if nodes remain, transfer manager inner state, limiter, watcher tasks, and runner joins to one owned reaper that continues metered cleanup until all settle. Caller return never destroys permit state;
   - concurrent tool futures therefore cannot let an early child, prompt drop, timeout, or cancellation resume parent execution while capacity is owned elsewhere.
   This is an internal scheduling primitive, not the public PR 5 wait API.
5. Keep `plugins.task.max_concurrent` registered so existing configurations continue to parse, mark it deprecated, and use its process-wide semaphore only as the fallback for unmanaged headless/ACP/SDK/print sessions until PR 9. Managed sessions do not acquire or receive that semaphore because `[agent].max_concurrent_agent_turns` is authoritative per outer session. Do not alias the values because their scopes differ. Remove the blocking `task` composite’s separate outer semaphore acquisition; both blocking and background paths pass the fallback to `maki.agent.session`, whose adapter conditionally uses it only when no manager context exists. Document the split and never enforce both limits on one turn.
6. Prove with channel/barrier tests, never sleeps, that sibling fan-out respects the cap, two concurrent blocking child prompts share one parent lease at cap one, the first prompt's immediate post-return marker remains blocked until the second suspension ends and physical ownership is restored, a parent waiting on one or several children yields capacity, recursion at a saturated limit completes, cancellation of one of several child waits does not reacquire early, dropping the sole prompt future while another turn owns the permit prevents all post-cancellation parent code until the outer poll gate reacquires, cancellation cleanup itself reacquires/owns a permit before any backend poll, shutdown closes admission then drains metered cancellation cleanup before limiter teardown, and cancellation before admission calls neither the backend method nor constructs/polls its future while terminalizing the ticket exactly once. Add a held-backend shutdown test that observes one bounded graph-wide timeout report, then releases the backend and proves the reaper still meters cleanup and eventually retires all joins/permits. Assert all permit/suspension counts return to zero after setup failure/future-drop paths.

#### Phase 3: Implement graph lifecycle, limits, and cancellation

1. Enforce limits under the graph lock at reservation time:
   - root depth is 0 and children are parent depth + 1;
   - live count includes reserved/live root and descendants, excludes closed/removed tombstones;
   - per-parent fan-out includes reserved/live direct children, excludes closed/removed children;
   - a node remains spawnable after an ordinary turn completion/failure/user cancellation, but not after close/remove/shutdown.
2. First add a narrow actor integration operation, `cancel_existing` (final name idiomatic), that establishes one reusable cancellation cut atomically against actor admission, queue pop, and active installation under the actor’s own state/queue linearization protocol. It cancels the active turn and terminalizes queued turns belonging to the cut while leaving the actor open; work admitted after the cut survives. Replace `AgentActorHandle::cancel_all` internals/callers with this operation where reusable cut semantics are required. Add an actor test barrier exactly between queue removal and active installation to prove no turn can miss the cut.
3. Define manager operations with explicit semantics:
   - `cancel_agent(id)` is reusable and invokes that node actor’s atomic reusable cut, affecting only work present at the actor cut while leaving the node open;
   - `cancel_subtree(id)` captures the node plus all then-reserved/committed descendants at one graph revision, releases the graph lock, then composes one atomic actor cut per captured node; descendants committed after the graph cut are excluded;
   - `close_subtree(id)`/remove is permanent: atomically marks the cut closing, rejects new descendants/work through manager handles, releases the lock, closes each actor, and marks/tombstones nodes when settled;
   - `shutdown` atomically stops all graph admission, captures all live nodes, computes one absolute deadline from the existing three-second TUI `AGENT_SHUTDOWN_TIMEOUT` policy (relocated/shared with the manager), and passes that same deadline to the aggregate join. It returns disjoint `ShutdownReport { joined, timed_out }`; on timeout, one manager-owned reaper immediately takes the limiter/inner state, wait watchers, and every outstanding join until all actors settle. Bounded return therefore reports current completion rather than claiming every node has already joined.
4. Linearize spawn versus cancellation:
   - a child reserved before a reusable graph cut is included; after its factory commits, the manager must apply its captured actor cancellation generation before exposing it live;
   - a child reserved/committed after the reusable graph cut survives;
   - admission before an actor cut is cancelled while admission after it survives, including the queue-pop/active-install boundary;
   - permanent close/shutdown marks ancestors/cut nodes first, so no child can commit beneath them afterward;
   - factory failure and concurrent close always remove reservations and restore capacity exactly once.
5. Dropping user-facing handles must not cancel work. Manager/runtime task ownership keeps nodes alive. Closing/removing a child does not close ancestors or siblings. Closing the root subtree closes the graph’s live nodes but leaves snapshots/tombstones available until manager drop.
6. Keep closed node metadata in manager snapshots for the outer-session lifetime, while excluding it from live limits. Do not persist it in this PR.
7. Add actor/manager deterministic tests for topology, nested spawning, all four limits, typed errors, reservation rollback, reusable exact-node/subtree cancellation, the queue-pop/active-install gap, admission before/after actor cut, permanent subtree close, sibling isolation, spawn/cancel races, manager shutdown, task ownership after handle drop, and graph snapshots.

#### Phase 4: Build a deterministic TUI runtime harness and make the outer session own the manager

1. Refactor reset/load/rewind into immutable `SessionReplacementRequest`s before adding manager replacement. `App::reset_session`, `load_loaded_session`/`apply_loaded_session`, and `rewind_to` must no longer checkpoint-then mutate the live App, rotate/bind command targets, clear history mirrors, fire replacement/restore callbacks, acquire/release session locks, install a provider, change global UI state, or alter chats/session/permissions/UI before commit. Each request contains candidate `AppSession`, history/model request, replacement kind, deferred UI/input/command/autocmd/lock effects, and rewind restoration data. A pre-replacement checkpoint may occur only as an explicit write of current state and cannot alter live routing.
2. Replace direct `SpawnCtx::spawn_runtime` reuse with a two-stage `PreparedSessionRuntime::prepare(...) -> Result<Self, _>` and synchronous/no-await `activate(...) -> SessionRuntime` boundary:
   - `prepare` constructs private App state, permissions, manager/root resources, handles, shell/notification state, and buffered display/restore/queue work, but is inert: it does not bind a command-registry target, mutate scrollbar/global UI settings, install into the shared provider/model slot, emit restore/autocmd requests, flush/admit queued work, claim/release live session locks, or expose an actor mailbox/route;
   - split `App::new` and `restore_display` into pure/private preparation plus activation so history/display can be built with restore emissions buffered and no shared side effects;
   - if actor construction must start a runner during preparation, keep its mailbox/routes private and make `PreparedSessionRuntime::drop` shut it down/join or detach a guaranteed-closing task; no work can reach it before activation;
   - add a non-cloneable `maki-storage::session_lock::ClaimedSessionLock` with a random owner token and a backward-compatible ephemeral lock record `PID OWNER_TOKEN`. Parsing continues to accept legacy PID-only records for cross-version claim/open checks; this changes only `.lock` coordination files, never stored session/history format. `claim` returns the sole lease; `heartbeat(&mut self)` and `release(self)` lock and compare both PID and token, never create/reclaim after lease revocation, and stale/replaced guards become no-ops rather than deleting or recreating another owner’s lock;
   - migrate every TUI lock path, not only replacement: initial startup/`push_runtime` claims a lease into `SessionRuntime`; periodic heartbeat batches operate on current lease identities and revalidate the token at execution time; `remove_runtime`, focused load/replacement, and process exit consume/release guards. Eliminate detached work that captures only session ids. ACP/SDK legacy free-function use may remain only if an explicit source audit shows those deferred frontends still need it;
   - for same-session-id replacements such as rewind, retain the existing runtime’s exact guard continuously and transfer it at activation with no filesystem operation. For different ids, after all other preparation succeeds, synchronously claim the target as the final fallible precommit step; the guard releases only that target on abandoned commit and transfers into the activated outer runtime/lock owner on success. Release the distinct old guard only after activation;
   - `activate` performs one no-await commit that binds the command target and routes, installs the selected model/provider, applies global UI state, transfers the prepared/existing lock guard, publishes history, swaps the runtime slot, and only then emits buffered restore/autocmd/queue effects exactly once.
   Add a `RuntimeHarness` with injectable failures after every inert preparation stage and at the final target-lock claim. It exposes complete App/session state, command-registry target count, provider slot identity, global UI state, session-lock ownership, restore/autocmd streams, queue admissions, permissions, command target, run id, pending queue, manager/root ids, routes, and old-manager shutdown.
3. Add `AgentManagerHandle` to `SessionRuntime` or make it unambiguously owned through `AgentHandles`; construction in `SpawnCtx::spawn_runtime` creates one manager from the outer session’s resolved `AgentConfig`, then creates its root through the host factory. Different tabs receive distinct managers and graphs.
4. Refactor `AgentHandles::spawn`/`spawn_agent_internal` to accept the manager/root factory result rather than generating `AgentId` and calling `AgentActorHandle::spawn` directly. Preserve shared-history publication before handles escape, event channels, queue facade, mailbox, MCP handle, provider slot, permissions, dynamic prompt/tool setup, and all PR 2 root adapter behavior.
5. Execute every `SessionReplacementRequest` as a whole-`SessionRuntime` transaction:
   1. checkpoint the old session without mutating its live App/routing;
   2. call inert `PreparedSessionRuntime::prepare`; on any error, drop/close only private candidate resources and leave old state plus every shared registry/slot/global/lock/event stream unchanged;
   3. resolve lock precommit by identity: same id borrows/marks transfer of the old `ClaimedSessionLock` without I/O; different id claims a new guard as the final fallible step, and abandonment releases only that target;
   4. call no-await `activate` to bind routes/target, apply shared model/UI state, transfer the lock guard, publish history, and atomically replace the runtime slot;
   5. commit deferred UI/input/command-target changes and fire replacement/restore autocmds with required old/new identity, then flush buffered restored work exactly once;
   6. if ids differ, release the old lock only after the new runtime owns its target lock and routes; for same-id replacement never release/reclaim it. Then initiate old-manager shutdown and detach or collect its join task without blocking new input.
   Old events remain harmless through the per-tab generation/run-id filter, which advances only at activation. Activation operations must be designed infallible or have explicit compensating rollback before any event/work publication. This PR has no in-place root-runtime replacement API.
5. Replace TUI graph-wide cancellation fan-out:
   - root `CancelAll` uses manager `cancel_subtree(root_id)` instead of actor plus `subagent_cancels.cancel_all()`;
   - process exit/outer-session replacement uses manager shutdown/close semantics;
   - `Cancel { run_id }` remains root actor correlation cancellation, not graph identity;
   - child interactive cancel routes by internal `AgentId`/manager handle or the existing stamped `SubagentCancel` closure, not by treating `parent_tool_use_id` as identity.
6. Add `agent_id: AgentId` to every live `SubagentInfo` envelope as non-serialized runtime metadata (`#[serde(skip)]`) and make it mandatory for manager-created children. Replace all live TUI `chat_index`, `subagent_channels`, stamped-outcome deduplication, history routing, input routing, and child-cancel keys with `AgentId`; retain `parent_tool_use_id` only as visible label, provider/tool correlation, and legacy storage field. A restored display-only child tab has no live `AgentId`, remains addressable only by its isolated stored presentation key, has no live input/cancel channel, and is never inserted into live manager maps. Two live children with the same compatibility string must produce separate tabs/channels and independently route input, cancellation, outcomes, and history.
7. Keep public task ids unchanged but make collision behavior explicit: normal task plugin creation remains collision-free because each model tool invocation has a unique provider tool-use id and the no-tool-id fallback generates a fresh `MakiId`. The task table rejects an unexpected duplicate instead of overwriting an existing entry. Duplicate compatibility ids are nevertheless supported for lower-level/direct `maki.agent.session` callers and TUI routing because `AgentId` is the live key. Add both duplicate-session routing tests and a task duplicate-rejection regression.
8. Remove the TUI-owned role-specific `CancelMap<String>` from managed root coordination once all live managed children route through the manager. Keep only an explicitly named compatibility fallback for deferred unmanaged frontends if compilation requires it; structural tests must prevent that map from becoming graph identity again.
9. Preserve all existing app behavior: flat child chat/task picker, async child outliving its spawning root turn, stamped terminal deduplication by `(AgentId, TurnId)`, root stale-event filtering by `run_id`, child input and paste, failure detail, respawn channel behavior, and queue/drain ordering. PR 8B, not this PR, renders the graph.

Do not generate `AgentId` or call `AgentActorHandle::spawn` directly. Preserve current provider/model/system/tools/local-tools/audience/MCP/thinking/fast construction as adapter-owned state until PR 4.

Store `spawned_by_tool_use_id` only as optional compatibility metadata. ### Risks, Blockers, and Required Decisions

- **Settled limits:** Use the operator-selected balanced defaults: 8 active turns, depth 4 with root depth 0, 16 live direct children, and 64 live nodes including root. Closed/removed tombstones do not count; reusable terminal turns do not close nodes; nesting is allowed until PR 4 policy narrows it.
- **Manager versus actor ownership:** The manager must not duplicate actor queue/history/outcome state. Keep actor tasks manager-owned without an `Arc` cycle: runtime tasks and backend contexts should hold weak manager references or narrowly scoped capabilities. `WatcherRegistry` owns watcher task handles outside `TurnPermitLease`; the lease stores only ids/triggers/completion state, while watcher-held state keeps the lease alive until guard retirement. `ManagedExecutionFuture::drop` closes registration, signals all watchers, releases any permit, then revokes the turn guard; registry/reaper ownership joins remaining watchers.
- **Factory rollback race:** Actor/backend construction can fail after graph reservation. A reservation token/generation must make commit/rollback idempotent and prevent a close/shutdown race from resurrecting the node.
- **Capability staging:** PR 3’s opaque turn-bound capability is deliberately narrower than the comprehensive PR 4 policy/grant design, but its interface must support later ceiling intersection. Do not expose `Arc<AgentManager>` as unrestricted authority through `ToolContext` or Lua.
- **Concurrency deadlock:** Counting root and child active turns under the shared cap requires suspension. A synchronous guard cannot reacquire in `Drop`; correctness lives in `ManagedExecutionFuture`’s asynchronous pre-poll gate. Suspension drop only marks/wakes. Every poll of an already-started opaque backend, including cooperative cancellation cleanup, requires physical ownership; shutdown drains metered cleanup before limiter teardown.
- **Cancellation semantics:** Reusable interactive cancellation and permanent task despawn are distinct. `cancel_agent`/`cancel_subtree` leave nodes open; close/remove/shutdown reject future work/spawn. First terminal/cancellation state still wins inside each PR 2 actor.
- **Compatibility identity:** Duplicate sessions can share a `tool_use_id`; any compatibility mapping must be one-to-many or node-local. Never make a string tool id a unique graph key. Restored static child tabs have no live node until PR 6 and must remain display-only.
- **Outer-session replacement:** Current App construction/reset/load/rewind has shared side effects before action handling (`App::new` command/global binding, restore callbacks/queue flush, provider slot and session-lock changes). PR 3 must use immutable requests plus inert `PreparedSessionRuntime::prepare` and no-await activation. Candidate failure leaves every registry/slot/global/lock/route/event stream unchanged; prepared-resource drop closes private actors. There is no in-place root replacement API.
- **Lua invocation scope:** `LuaSession::prompt` has no `ctx` parameter and sessions outlive creation turns. It must read the caller’s current managed token/lease from the existing `TaskCell`/`TaskScope`/`ScopedFuture` invocation scope at call time. Never retain creation-turn authority in the session; detached scopes carry none.
- **TUI testability:** Existing event-loop tests lack cheap `SessionRuntime` construction and deterministic replacement failure injection. Building the scoped `RuntimeHarness`, immutable request tests, and injectable test root factory is part of this PR, not an optional manual check.
- **Deferred frontends:** Headless, ACP, SDK, and print still construct low-level agents directly by design until PR 9. Keep the exception explicit in code/docs/structural tests rather than weakening the manager-only invariant for migrated TUI sessions.
- **Task option migration:** Keep `plugins.task.max_concurrent` parsed and deprecated, with no alias because it is process-scoped. It remains effective only as the unmanaged-session fallback; managed sessions use only `[agent].max_concurrent_agent_turns`. The session adapter, not two plugin layers, conditionally acquires the fallback.
- **No persistence yet:** Graph snapshots and tombstones are in-memory projections only. Do not serialize them or reinterpret legacy stored subagent tabs; PR 6 will define durable identity and restart behavior.
- **Working tree:** Preserve all unrelated session-start untracked files and do not include them in implementation commits.
